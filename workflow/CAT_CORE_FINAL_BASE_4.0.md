# CAT CORE FINAL — BASE 4.0（正式基线）

状态：正式规则基线  
版本：BASE 4.0  
适用范围：赛前足球赛事分析、预测封存、赛后审计  
治理原则：增量融合；历史档案只读保留；实验模块不得未经验证进入正式层。

## 1. 系统目标与边界

首要优化目标是提升胜平负（1X2）方向判断的准确性。比分允许存在误差，但不能以比分命中掩盖胜负方向错误。系统是风险分析与决策支持工具，不承诺赛果，不将概率判断包装为确定结果。

大模型负责综合证据并作最终裁决。模块输出是证据和诊断，不以固定百分比权重公式代替最终判断。不得使用“最低赔率一方必胜”等规则。欧赔、亚盘、资金、赔率变化和庄家压力仅作为模型输出后的辅助异常校验，不得反向主导球队实力判断。

第三方模型、媒体预测和外部分析只作交叉参考，不采用简单多数票替代独立推演。

## 2. 正式架构链

数据完整性  
→ 比赛环境/变量  
→ 球队真实实力  
→ Goal Structure Engine 3.0  
→ 比赛脚本  
→ 1X2结果模型  
→ 让球/大小球/半全场  
→ 市场异常校验  
→ MR / BPI / CBC / TTE / RSE  
→ LLM最终裁决。

各环节必须保留可追溯输入、结论和未知项。信息不足时降低置信度或 PASS，不得用臆测填补缺失数据。

## 3. 分析证据优先级

1. 数据完整性与来源可信度、更新时间。
2. 比赛环境与变量：赛事阶段、主客场、赛制、天气/场地（可得时）、裁判（可得时）。
3. 球队真实实力与战术匹配。
4. 伤停位置、球员重要性、替补质量及体系稳定性。
5. 近期表现与赛程负荷。
6. 战意、积分/晋级形势、轮换可能性。
7. 比赛脚本与主客进球结构。
8. 独立1X2判断。
9. 市场数据异常校验。

伤停必须按位置、作用和替代方案评估；轮换不自动意味着进球上限下降。两回合赛事必须考虑首回合比分、晋级条件和战术目标。

## 4. Goal Structure Engine 3.0

必须先独立估计主队进球结构与客队进球结构，再生成比分矩阵。不得先挑比分再倒推进球结构或胜负方向。

可用输入包括：总xG、运动战xG（open-play xG）、定位球xG（set-piece xG）、非点球xG（non-penalty xG）、射门质量/数量、禁区触球、转换进攻、防守失误、定位球防守等。数据缺失时明确标注，不得虚构xG。

输出至少包含：
- 主队预期进球区间/核心落点及依据；
- 客队预期进球区间/核心落点及依据；
- 进球环境与尾部风险；
- Score Cluster比分簇及合理比分矩阵；
- 4+进球及其他尾部情景是否触发。

Goal Structure与1X2结果模型解耦：进球总量、双方进球数和胜平负分别判断，再由LLM综合检查逻辑一致性，不强制相互绑定。

## 5. 情景与正式模块

每场按信息量构建A/B/C情景；确有必要时增加D情景。情景需说明触发条件、比赛脚本、主客进球结构和对1X2的影响。

正式模块：
- MR（Model Reversal）：反转测试，检查核心假设变化是否导致方向翻转，以及翻转是否有证据。
- CBC（Conservative Bias Control）：监控过度保守、平局偏好或热门回避，防止系统为规避风险而错过真实方向。
- TTE（Tail Trigger Engine）：识别高比分、崩盘、红牌/早球等尾部风险；触发条件必须记录。
- Score Cluster：比分簇管理，不以单一比分代表完整分布。
- RSE（Result / Score-difference / Expected-goal stability）：分别评估胜负结果、净胜球和进球结构稳定性。
- BPI（Bookmaker Payout-pressure Indicator）：只作庄家赔付/市场风险校验，不可独立决定方向。
- DBI：防线崩盘风险诊断。
- DSR：比分输出置信度与比分覆盖管理。
- H2H增强、阵容重叠率、HT状态与HT→FT转移等作为辅助证据，不可凌驾于当前实力和阵容事实。

MR、CBC、TTE、RSE等模块应输出可审计的触发理由；不得只给标签而无证据。

## 6. 市场异常校验

在独立模型形成初判后，才检查欧赔、亚盘、资金分布/集中度、赔率变化、盘口水位、赔付压力及其背离。重点检查：
- 欧赔、亚盘与资金方向是否背离；
- 市场热门是否真实，是否存在过度聚合；
- 主胜过度聚合或热门客队风险；
- 市场变化是否与阵容/战术事实一致；
- 市场信号是否仅反映公众偏好而非基本面。

市场证据可要求复核，但不得因赔率低或资金集中而自动改判。记录市场数据的来源和抓取时间。

## 7. 赛前工作流与数据核验

赛前先核对：比赛编号、赛事、开球时间及时区、主客队、赛制/阶段、官方让球数（如适用）、赔率与盘口时间戳、伤停、预计/正式首发、轮换信息、数据来源。

不同来源发生冲突时，先列出冲突与来源，不静默择一。将信息分为：
- 已确认事实；
- 有来源但尚未确认的信息；
- 模型推断；
- 缺失/未知。

首发公布后可生成独立的赛前更新版本，保留旧版本，不覆盖原预测。

## 8. 强制预测输出模板

每场至少分别给出：
1. 胜平负（主胜/平/客胜，最好同时给出概率或概率区间及置信等级）；
2. 让球胜平负（必须注明官方让球数；未提供时写“让球数待核验”，不得自行假设）；
3. 进球数（单一主判断：0/1/2/3/4/5/6/7+，并说明邻近区间风险）；
4. 比分（先主客进球结构，再列核心比分簇及必要的尾部比分）；
5. 半全场（独立判断，不从全场胜负机械推导）。

另须给出：
- 比赛事实核验与数据缺口；
- 球队实力、伤停、替补、赛程、战意；
- A/B/C情景与触发条件；
- 1X2独立判断依据；
- 市场异常校验（如有可靠数据）；
- MR/CBC/TTE/RSE检查；
- 风险标签、置信等级与PASS理由（如适用）。

低信息、低价值或数据冲突无法解决的赛事可以PASS/简报，不为凑场次而强行给结论。以上是研究分析输出规范，不构成投注指令或收益承诺。

## 9. 赛前封存与赛后审计

赛前记录必须保存预测时间、数据截止时间、模型版本、输入来源和完整输出。封存后不得回写覆盖；任何临场更新作为新版本追加。

赛后记录实际比分、半场比分、红牌/点球等关键事件（可核验时），逐项评估：
- 1X2方向是否正确；
- 让球方向是否正确；
- 总进球判断误差；
- 主客进球结构误差；
- 比分簇覆盖情况；
- 半全场判断误差；
- 情景触发是否发生；
- 数据/事实错误、模型判断错误、尾部事件、执行/记录错误。

复盘必须区分“方向正确但比分错误”与“方向错误”。不得用赛后信息伪装赛前已知，不得只挑成功样本。

## 10. 变更治理与版本管理

- BASE 4.0为正式稳定基线。
- 正式模块不得被新模块直接删除、替换或静默修改。
- 新规则先登记在实验层，说明假设、输入、触发条件、适用范围和潜在副作用。
- 与稳定基线并行回测，使用相同比赛样本、相同信息截止点和相同评价口径。
- 先预注册指标和晋升门槛；没有足够样本或统计证据时，保持实验状态。
- 晋升需证明对核心目标（尤其1X2方向）有稳定增益，同时检查校准、覆盖率、不同联赛/赛制分层和副作用。
- 若表现退化，回滚实验版本，不破坏BASE 4.0和历史记录。
- 禁止未经验证的自动调权、事后改规则或只根据少数个案升级。

## 11. 风险与责任边界

任何预测均存在不确定性。概率必须经过样本校准后才能称为校准概率；样本不足时只标注为模型估计。系统不得承诺命中、稳定盈利或“稳胆”。预测结果用于研究和风险识别，不应替代个人财务判断。
