# CAT CORE FINAL — Experimental Modules Register

状态：实验治理规范  
适用基线：BASE 4.0  
核心原则：新模块只增量接入，不删除或替换正式模块。

## 1. 实验登记要求

每个实验必须先登记唯一ID，并填写：
- 名称、版本、负责人/提出来源、登记日期；
- 要解决的问题及可证伪假设；
- 作用环节和预期影响（尤其是否影响1X2方向）；
- 输入字段、数据来源、时间截止点；
- 触发条件、输出定义、缺失数据处理；
- 适用联赛/赛制/场景及明确排除范围；
- 潜在副作用和失效条件；
- 对照基线版本；
- 预先定义的评价指标、分层方式和晋升门槛。

未完成登记的想法不得写入正式推演链。

## 2. 并行回测设计

- 稳定基线与实验版本必须使用相同比赛样本、相同赛前信息截止时间和相同数据口径。
- 尽可能采用时间外样本或滚动验证；不得用未来信息回填赛前输入。
- 预测必须在开赛前封存；实验组与基线组均保留原始输出。
- 不得只挑选实验有利的联赛、比赛或时间段。
- 按联赛、赛制、热门程度、主客场、数据完整性等维度检查异质性。
- 同时报告总体结果与样本量，避免少量样本造成虚假提升。

## 3. 核心评价指标

首要指标：
- 1X2方向准确率；
- 1X2概率质量（如有概率输出，使用Log Loss、Brier Score及校准分析）；
- 各方向（主胜/平/客胜）的分层表现，检查类别偏差。

辅助指标：
- 让球方向准确率；
- 总进球绝对误差；
- 主客进球结构误差；
- 比分簇覆盖率（必须事先定义簇的范围）；
- 半全场准确率；
- PASS覆盖率与被PASS比赛的事后表现；
- 数据缺失率、输出稳定性、不同联赛/赛制的退化情况。

不得用比分命中率替代1X2核心目标，也不得只报告准确率而忽略概率校准、样本量和置信区间。

## 4. 晋升、保留与回滚

晋升前必须预先确定：
- 最小有效样本量及其统计依据；
- 主要指标和最低改善幅度；
- 置信区间/显著性或其他不确定性判断；
- 可接受的副作用上限；
- 适用范围和失败条件。

当前尚无经用户确认的统一样本量或数值晋升门槛，因此本文件不擅自设定。每个实验须在开始回测前单独预注册门槛；未预注册或样本不足时只能标记“证据不足”。

晋升状态：
- proposed：待评审；
- registered：已登记、未回测；
- testing：并行测试中；
- evidence_insufficient：证据不足；
- promoted：达到预注册门槛并批准进入正式层；
- rejected：未达到门槛；
- rolled_back：曾晋升但后续监测退化，已回滚。

实验未晋升前不得改变BASE 4.0正式输出。晋升后仍保留旧基线版本与变更记录；不得删除历史数据。

## 5. 实验登记模板

| 字段 | 内容 |
|---|---|
| experiment_id | EXP-YYYY-NNN |
| name_version | 模块名称与版本 |
| hypothesis | 可证伪假设 |
| target_problem | 目标问题 |
| affected_stage | 架构链环节 |
| inputs_sources | 输入字段与来源 |
| trigger_logic | 触发逻辑 |
| output | 输出定义 |
| scope | 适用范围 |
| baseline | BASE 4.0及具体提交/版本 |
| sample_period | 样本时间范围 |
| sample_size_rule | 预注册样本量依据 |
| primary_metric | 首要指标 |
| guardrails | 副作用监控指标 |
| promotion_threshold | 预注册晋升门槛 |
| result | 结果及不确定性 |
| status | 当前状态 |
| decision_log | 晋升/拒绝/回滚理由 |

## 6. 防止回测污染

- 禁止用赛后解释改写赛前预测。
- 禁止重复挑选同一批失败样本直到“看起来有效”。
- 若使用历史样本开发模块，必须另设未参与开发的验证样本。
- 对同一批样本反复试验多个规则时，明确多重比较和过拟合风险。
- 对缺少赛前预测封存记录的旧比赛，只能做赛果分布或事后诊断，不能计入严格的赛前命中率。
